# Installation with Python 3.13 — 2026 migration

The default `Pipfile` has been updated to a Python 3.13 dependency profile. The original version constraints are preserved in `Pipfile.legacy`, and its historical lockfile in `Pipfile.legacy.lock`. The stale lockfile was removed from the default path so a new compatible lock can be generated by Pipenv. The compatibility migration has passed isolated dependency installation, application import, shell initialisation, local model tests and Docker startup in GitHub Actions; the full external scanning tool suite remains unverified.

## Test the environment (never scans)

```bash
python3 scripts/doctor.py
python3 scripts/doctor.py --offline --json
```

The first command performs DNS lookups for `github.com` and `pypi.org` but does not connect to services, install software or scan hosts. The second command is entirely offline.

## Direct virtual environment installation

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-modern.txt
python -c 'import cmd2, luigi, sqlalchemy, yaml; print("imports OK")'
python pipeline/recon-pipeline.py
```

## Pipenv installation (the default)

```bash
python3 -m venv "$HOME/.pipenv-venv"
"$HOME/.pipenv-venv/bin/python" -m pip install pipenv
export PIPENV_IGNORE_VIRTUALENVS=1
export PIPENV_VENV_IN_PROJECT=1
"$HOME/.pipenv-venv/bin/pipenv" install
"$HOME/.pipenv-venv/bin/pipenv" run python scripts/doctor.py --offline
"$HOME/.pipenv-venv/bin/pipenv" run python pipeline/recon-pipeline.py
```

A fresh `Pipfile.lock` is generated on first install. No sudo, pip's `--user` flag, `--break-system-packages`, certificate bypass or unreviewed `tools install all` is required.

## Current compatibility boundaries

- The default requires Python **3.13**; a compatible Python interpreter and working PyPI access are necessary. The primary CI build tests 3.13; the dependency-free preflight also tests Python 3.11.
- `cmd2>=2.6.2,<3` avoids the known breaking 3.x and 4.x releases.
- `SQLAlchemy>=1.4.54,<2` preserves legacy ORM APIs. The 1.4 series is EOL and should be migrated separately to SQLAlchemy 2.x once all models and queries have tests.
- `PyYAML>=6.0.2,<7` avoids the old 5.4.0 source-build failure.
- Native scanners, installers, privileged commands, platform-specific networking and Termux are not certified by these smoke tests. Docker builds and shell startup passed on GitHub Actions; live Docker-based scans have not been tested. Use the framework only on owned or explicitly authorised systems.
- Do not use `Pipfile.legacy` outside an appropriately isolated environment; its older dependencies are unsupported. See [INSTALL-RECOVERY.md](INSTALL-RECOVERY.md) for network and environment troubleshooting.

If the shell does not start after installation, record the **first** traceback and a redacted `python -m pip freeze` output. Do not launch active scans as a troubleshooting step.
